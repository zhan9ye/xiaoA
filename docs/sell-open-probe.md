# 开售探测 + 共享代理池：彻底改造设计与实施记录

状态：**实施中**  
共识日期：2026-07-31  
文档路径：`docs/sell-open-probe.md`

---

## 1. 为什么要彻底重塑

当前逻辑以**墙钟开售时间**为准开火，但上游真实开门时间抖动；未开与收工文案相同；代理按「用户×倍数」静态绑定，与真实子账户需求、IP 频控都不匹配。结果是：容易打在未开上烧掉出口，或开门后反应过慢，**很难卖出去**。

改造原则：**探测是核心；侦察代理可烧；售卖代理用共享池+冷却；Runner 提前待命，探测拉闸后开火。**

---

## 2. 上游行为（实测）

| 状态 | `ACE_Sell_Son` 表现 |
|------|---------------------|
| **未开** | 约 **300ms** 内返回；`Error:true`，Msg 含 `当前可售额度已达上限.本日交易通道已关闭` |
| **已开** | 请求**长时间挂起**（进入服务端排队） |
| **当日收工** | **与未开同一文案**（快返回） |

匹配前缀：

```text
当前可售额度已达上限.本日交易通道已关闭
```

因此：**不能靠文案区分未开/收工**；在开售探测窗内快返回该文案 = 未开；**超时未完整返回 = 已开**。窗外再将该文案当收工。

## 4. 开门探测

### 4.1 角色

- 专用**探测账号**（平台配置，非普通用户任务）。
- **侦察池**与售卖池隔离。
- 命中后：`sell_open_event.set()`，唤醒**已待命** Runner（禁止此时才 Login/拉子账号）。
- 探测窗口结束仍未命中：时钟兜底开火。

### 4.2 每轮

- 默认 **2 代理并行**（可配 3～4；探测优先，不怕烧代理）。
- Client 等待见「相对基线」。
- 判定：
  - ≥1 路时限内返回且为关闭文案 → **未开**
  - ≥1 路时限内返回且非关闭文案 → **已开**
  - 两路均未完整返回 → **已开**，abort 探测并拉闸
- 每代理连续默认 2 次，第 3 次易 429；第 2 次即 429 → **报警**并可降安全次数。
- 轮次间隔建议 30～50ms。
- 仅在 `[T_open, T_open+W]` 探测。

### 4.3 相对基线：开门超时

| 项 | 建议初始 |
|----|----------|
| default | **350ms** |
| min | 250ms |
| max | 500ms |
| margin | 50ms |

`effective = clamp(baseline_p95 + margin, min, max)`；样本不足用 default。

### 4.4 探测冷却 ≠ 售卖冷却

| 项 | 探测 | 售卖 |
|----|------|------|
| 现象 | 间隔约 2～3s 可免 429（不稳） | 约 11s / 529 类频控 |
| default | **3000ms** | **11000ms** |
| min～max | 如 2000～5000 | 可另配 |

两套参数，禁止混用。

### 4.5 管理端独立校准

- 手动开/关；默认关。
- 只用侦察账号+侦察池；与正式开门探测互斥。
- 结果打印管理端：样本、P50/P95、建议 default、429、代理用量。
- 可「应用建议」；写入仍 clamp 到 min～max。
- 校准两类：`open_timeout_default_ms`、`probe_cooldown_default_ms`。

## 5. 共享售卖代理池

- 取消「每用户 × 倍数」静态主模型。
- `acquire` → 请求 → `release(sell_cooldown)`；无可用则 **FIFO** 等待。
- 第一波容量：

\[
\lceil (\sum 当日待售子账户数) / 2 \rceil + 预留
\]

- Cookie 按用户会话，不按代理串号。
- 同用户同一代理并发子账户 ≤ 2（上游规则）。

---

## 6. Runner 联动

1. 开售前：Prep（Login、子账号、助记词）+ 连接预热，阻塞在开门闸门。
2. `T_open` 起探测开始；命中则 Event 释放。
3. HotWindow 从**共享售卖池**借代理开火，用毕归还冷却。
4. 探测窗内禁止把关闭文案当「当日收工」；窗外或开火后的收工逻辑保留。

---

## 7. 购机与释放（代理池激活窗）

相对**全站开售时间** `T_open`：

| 时刻 | 动作 |
|------|------|
| **T_open − 40 分钟** | 购机 + Login 探测放行（激活窗开始） |
| **T_open ∼ T_open+10 分钟** | 池保持可用（售卖进行中） |
| **T_open + 10 分钟** | 自动释放未锁定实例 |

可配：`PROXY_POOL_ACTIVATE_MINUTES_BEFORE=40`、`PROXY_POOL_RELEASE_MINUTES_AFTER=10`。  
容量：售卖池按待售近似公式 + 预留；侦察池单独标角色。旧固定 `HOUR:MINUTE` 购机/释放已弃用。

## 10. 风险与非目标

- 多机部署时 Event/池状态需外置（当前按单机进程内实现）。
- 校准与正式探测互斥，避免参数与代理争用。
- 不在第一期做「阶梯盲打」；专注侦察兵 + 共享池。
